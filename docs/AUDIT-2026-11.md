# Audit, November 2026: UI/UX, functions, speed

Looked at as a commercial product. Three parts: the screens and workflows (operator's view), the job
functions (placement correctness, safety, data), and speed on the machine's own PC (Atom-class, WebKit
drawing on the CPU only, which also runs neoserver and grabs the USB cameras).

## Measured on the machine (from a LAN PC, no control taken)

| What | Cost | Note |
|---|---|---|
| `/api/status` | 200–540 ms | 4 × `systemctl` per call; every Wizard / Job file / Pad alignment visit. **Fixed: cached 10 s** |
| `/api/cam/grab` (scale 2) | 150–210 ms per frame, 256 kB | mostly the USB grab; a live picture asks up to ~6/s |
| `/api/mc/status` poll | 63 ms every 0.7 s per open screen | two serial transactions under the machine lock |
| Bulk page | 1.8 MB | the mosaic image, fetched again on every redraw |

## Still to do, by priority

### P1 (safety, lost work)
1. **Choosing a feeder in the list moves the head** (Feeder settings, bulk feeders): a "follow" toggle, off by default, or select-only with an explicit "To the pick point".
2. **Job questions are easy to miss**: a full-width question bar under the header on every page plus the buzzer; show an error when the answer did not reach the server. Questions should carry an id so a late double-click cannot answer the next one.
3. **STOP says "stopped" even when the request failed**: a persistent red banner then; "Stop job" vs "EMERGENCY STOP" wording.
4. **Calibration Save writes every pending Config.ini change**: save only the calibrated keys, show old → new, Apply / Cancel.
5. **A job can start while a camera tool drives the machine**; camera exposure / window can be changed by any client during a job: refuse while `busy` / `job_running`, set `job_running` before the thread starts.

### P2 (wrong results in some cases, friction)
- Re-import of a pick-and-place file (`repnp`) on a panel: all copies get the same row (use `match_copies` / `Comp.key`).
- Bulk pick angle sign (head-camera image y down vs nozzle CCW): add a sim test with a known turn; Setup view does not show the bulk turn.
- Camera angle added to vision-off parts (constant small turn).
- UTF-8 BOM job files lose their first line; job log stops after 500 lines (`log_n` capped).
- Non-atomic JSON writes (bulk containers, feedercheck, pads, camera.json, job usage).
- One unsaved-changes guard for every page (Save / Discard / Stay, `beforeunload`).
- The same feature in several places with different behaviour and names (marks: wizard vs job editor; vision type names; "Job settings" / "Job file settings" / "Job file").
- Wizard steps shown done when they are not; Options (machine-wide) inside the job wizard; no "Mount this job" at the end.
- Raw field names in the UI (`pick_height`, JSON dumps); free-text inputs for fixed choices (Whole / Mirror, Auto / Manual, tray type).
- Long operations without "n of N" and a real Cancel (Check feeders, mark search, measure).
- Toasts as the only error report (about 56 browser `confirm()` dialogs): errors inline at the action.
- Dangerous system actions (stop serbridge, install an update) without confirm or danger styling.

### Speed, still to do (biggest first)
1. **Live camera sends more than it shows**: at zoom ≥ 2 a full 1 MB frame for a quarter of it (the Mount screen's up camera at zoom 4). Crop on the server (`/api/cam/grab?zoom=`), never more than ~640 px.
2. **Whole-page redraws on small edits**: a click in the feeder list rebuilds the page, re-fetches the file list and restarts the camera; the components table rebuilds ~3,600 controls on a delete. Keep the list and camera, redraw the form only; delete rows in place; tabs as hidden panels.
3. **Status poll**: cache `/api/mc/status` ~0.4 s on the server, shared by all screens; 1.5 s on pages without a live picture; the header written only when it changes.
4. **Canvases redrawn on every poll** (coordinate cameras, table map): only when the position changed.
5. **Pocket / bulk-part search**: Config.ini read per request (cache by mtime); search only on a new frame and when the head is still.
6. **Bulk mosaic**: versioned URL + ETag, a ~1000 px picture.
7. **Startup**: 21 script files; load the page scripts on first use, or one bundle built by the server at start.

## Product ideas (what a mature commercial P&P UI has)
1. **Machine state banner**: Not homed / Homing / Idle / Running X / Paused, waiting for an answer / Error; every move button disabled with the reason.
2. **Job preparation checklist** per job (feeders loaded, pick points, heights, marks, board check) with pass / fail and a "ready to run" gate before Start.
3. **Undo / history** in the job editor, a diff before every save and every Config.ini write.
4. **Feeder loading view**: the feeder banks drawn, which reel where; barcode scan to confirm; low / missing parts warning.
5. **Operator and engineer roles**: Calibration, Settings, Files, Updates behind an engineer login.
6. **Live board view during the run**: placed / current / failed parts, click to skip or re-place.
7. **Alerts that reach the operator**: a question or error as a full-screen alert with the buzzer (light tower, phone).
8. **Production log and traceability**: boards, time per board, rejects per feeder / nozzle, CSV export, shift report.
9. **Reel counts**: decremented as parts are placed, "reel low in N boards".
10. **Built-in help**: a "?" beside each setting with a short explanation and a picture; guided calibrations with checks and roll-back.
